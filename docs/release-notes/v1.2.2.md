# Media Harvest v1.2.2 Release Notes

Media Harvest v1.2.2 fixes X (Twitter) and general site overlay downloads selecting late-fetched audio-only or video-only HLS rendition sub-playlists instead of the master playlist.

## Highlights

- **Master Playlist Priority Over Sub-Playlists:** Updated `handleTweetVideoDownload`, `handleSiteVideoDownload`, and `findMatchingStreamForDirectUrl` (`src/background/service_worker.js`) to rank master HLS playlists ahead of codec/resolution video sub-playlists (`avc1`, `hev1`, `vp09`, `av01`) and deprioritize audio-only URLs (`mp4a`, `aac`, `audio`, `DASH_AUDIO`).
- **Companion Audio Sub-Playlist Fallback:** When only split video and audio sub-playlists were captured without a root master playlist, `service_worker.js` pairs the sibling audio rendition (`audioUrl`) and `resolveStreamPlan` (`src/offscreen/offscreen.js`) fetches and muxes both tracks automatically.
- **Verification Coverage:** Expanded the automated suite to 144 unit and integration tests (`86.81%` line coverage).

## Verification

- `npm run check`: Syntax, i18n, manifest, and typography checks passed (68 files + companion scripts).
- `npm test`: 144/144 automated unit and mocked MV3 integration tests passed.
- `npm run test:e2e`: Chromium MV3 E2E suite verified on GitHub Actions `ubuntu-latest`.
